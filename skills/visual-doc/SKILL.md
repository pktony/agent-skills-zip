# /visual-doc

읽는 순서가 정해진 글(markdown) 대신, **한눈에 훑고 필요한 데만 파고드는 HTML 한 장**을 만든다.

```
/visual-doc <주제>              # 형식을 골라 HTML 1장 생성
/visual-doc <파일>              # 기존 md 를 HTML 문서로
/visual-doc <주제> --pattern <이름>   # 형식 지정
```

출처: https://thariqs.github.io/html-effectiveness/ — 20개 형식 카탈로그.
| 참고 | 내용 |
|---|---|
| `references/patterns.md` | 20개 형식의 **뼈대 · 언제 · 핵심 장치**. 형식을 고를 때마다 연다 (§절차 0) |
| `references/html-kit.md` | 토큰 · 스켈레톤 · SVG/JS 레시피 |

## 언제 HTML 이 이기나

| 상황 | 이유 |
|---|---|
| 여러 안을 비교 | 나란히 놓아야 비교된다. 세로로 쌓인 글은 비교가 아니다 |
| 분기·순서가 있는 흐름 | 화살표가 문장보다 정확하다 |
| 시간 축이 있는 사건 | 타임라인은 목록으로 안 된다 |
| 상태·수치가 여럿 | 카드/배지로 훑고 끝난다 |
| 만져봐야 아는 것 (인터랙션·애니메이션·파라미터) | 글로는 전달 불가 |

반대로 **줄글 3문단이면 끝나는 것은 markdown 으로 둔다.** HTML 로 감싸는 것 자체가 목적이 되면 안 된다.

## 형식 고르기

아래 표는 **후보를 좁히는 색인**이다. 답이 아니다 — 형식 이름과 한 줄 요약뿐이고
**뼈대도 핵심 장치도 없다.** 후보를 좁혔으면 `references/patterns.md` 에서 그 항목을 읽고 고른다.

| 무엇을 전달 | 형식 | 카탈로그 |
|---|---|---|
| 구현 계획 · 마일스톤 | 마일스톤 타임라인 + 요약 스트립 | `16 implementation-plan` |
| 선택지 N개 비교 (코드·기술) | 동일 템플릿 반복 + 지표 행 | `01 code-approaches` |
| 디자인 방향 N개 비교 | 시안 그리드 + 라이트/다크 토글 | `02 visual-designs` |
| 파이프라인 · 분기 흐름 | 인라인 SVG 플로우 + 클릭 상세 패널 | `13 flowchart` |
| 코드베이스 구조 | 모듈 맵 + 경계 설명 | `04 module-map` |
| PR 설명 · 코드 리뷰 | 주석 달린 diff | `03 pr` · `17 pr-writeup` |
| 디자인 시스템 · 컴포넌트 변형 | 토큰 표 + 라이브 샘플 | `05` · `06` |
| 인터랙션 · 애니메이션 시안 | 동작하는 프로토타입 | `07` · `08` |
| 다이어그램/일러스트 납품 | SVG 시트 + 다운로드 버튼 | `10 svg-sheet` |
| 발표 | 방향키 슬라이드 | `09 deck` |
| 개념 설명 | 점진 공개 + 조작 가능한 시뮬레이터 | `14` · `15` |
| 주간 현황 | 지표 카드 + 델타 | `11 status` |
| 장애 보고 | 심각도 배지 + 시각 타임라인 | `12 incident` |
| 값을 직접 고치는 화면 | 편집 UI (보드 · 플래그 · 프롬프트) | `18` · `19` · `20` |

애매하면 후보 2~3개를 집어 `patterns.md` 에서 **그 항목들만** 읽고 고른다.
표만 보고 고르지 않는다 — 이름만 맞고 알맹이가 빠진 문서가 나온다.
(실제로 그랬다: "개념적으로 설명" 요청에 표의 `15 concept-explainer` 를 못 보고
흐름도로 갔다가, 15의 핵심인 **조작 가능한 시뮬레이터**에 두 번 되돌아와서야 도착했다.)

## 규칙

1. **파일 1개, 자급자족.** CSS·JS·SVG 전부 인라인. CDN·외부 폰트·외부 이미지 금지 — 링크가 죽으면 문서가 죽는다.
2. **정보의 진실은 본문에 있다.** 그림에만 있는 사실을 만들지 않는다.
3. **클릭해야 보이는 정보를 만들지 않는다.** 접기·상세 패널은 *부연*에만. 핵심은 펼친 상태가 기본.
4. **꾸미기 금지.** 그라데이션·그림자·이모지 아이콘 없이 간다. 토큰 팔레트 하나(`html-kit.md`)로 끝낸다.
5. **좁은 화면에서 무너지지 않는다.** 다단 그리드는 `@media (max-width: 900px)` 에서 1단으로.
6. **인터랙션은 이유가 있을 때만.** 클릭 상세·방향키·슬라이더는 정보량을 줄일 때만 쓴다. 장식용 애니메이션 금지.
7. **식별자는 mono, 제목은 serif, 본문은 sans.** 값·경로·코드는 절대 본문 서체로 쓰지 않는다.

## 절차

0. **`references/patterns.md` 를 연다.** 표에서 후보를 좁혔어도 연다. 이 단계를 건너뛰고
   HTML 을 쓰기 시작하지 않는다 — 스켈레톤부터 손대면 형식이 아니라 즉흥이 된다.
1. 전달할 내용을 한 줄로 적는다 → 후보 항목을 읽고 형식 **하나**를 고른다.
2. 고른 형식을 **`<!DOCTYPE html>` 바로 아래 주석과 사용자 응답에 적는다** —
   `<!-- pattern: 15 concept-explainer -->`. 못 적으면 아직 고르지 않은 것이다.
3. `references/html-kit.md` 의 토큰·스켈레톤으로 시작한다. 스타일을 새로 발명하지 않는다.
4. 뼈대 순서대로 내용을 채운다. 채울 게 없는 섹션은 넣지 않는다.
5. **고른 항목의 `핵심` 줄을 다시 읽고 한 줄씩 대조한다.** 빠진 게 있으면 채운다 —
   형식을 골라 놓고 핵심 장치를 빼면 고르지 않은 것과 같다
   (`13` 의 "실패 경로를 반드시 그린다", `15` 의 "값을 만지게 한다" 가 그런 줄이다).
6. 브라우저로 연다. 좁은 폭에서도 확인한다. 만지는 장치가 있으면 직접 만져 본다.

## 다른 스킬과의 관계

- `/plan-well` 이 계획 본문을 쓰고, 그 흐름 문서를 이 스킬이 만든다.
- 그림 한 장이면 SVG 하나만 담은 최소 HTML 로 만든다. 형식을 억지로 채우지 않는다.
