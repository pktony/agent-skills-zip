# git-commit

커밋 메시지는 **명사형 종결(개조식)**. 장황함이 최대 적.

이 파일이 규칙의 원본. `~/.claude/hooks/git-commit-style.js` 훅이 커밋 직전에 이 파일을 읽어 보여준다.

## 규칙

1. **명사로 끝낸다.** `~한다 / ~했다 / ~합니다` 금지. `~함 / ~됨` 도 피한다.
   - ✗ `env_file 을 진짜로 교체하게 한다` → ✓ `운영 오버레이 env_file 교체`
2. **제목 한 줄, 50자 이내.** 넘치면 문장이 긴 게 아니라 커밋 범위가 넓은 것 — 쪼갠다.
3. **본문 없음이 기본.** 제목으로 안 되면 왜 그렇게 했는지만 1~3줄, 각 줄도 명사형.
4. **정보량 0인 말 금지.** `제대로`, `진짜로`, `깔끔하게`, `개선`, `최적화`, `리팩터링`.
5. **한 커밋 = 한 가지.** 두 갈래면 `·` 로 잇지 말고 커밋을 나눈다.
6. **무엇이 바뀌었는지 쓴다.** `수정`, `정리` 같은 한 단어는 규칙은 지켰어도 쓸모가 없다.

## 형식

```
<범위> <대상> <동작 명사>
```

동작 명사: 추가 / 제거 / 교체 / 이동 / 분리 / 통합 / 수정 / 이름 변경 / 복구

## 변환 예시

| ✗ | ✓ |
|---|---|
| 배포를 컴포즈로 옮긴다 — systemd 세 유닛을 없앤다 | 배포 컴포즈 전환 · systemd 유닛 제거 |
| 폴더 이름을 admin-api 로 바꾼다 | api → admin-api 폴더명 변경 |
| 위젯이 DB 를 거치지 않는다 — 카탈로그를 S3 에 굽는다 | 카탈로그 S3 정적 생성 |
| 겹침 보기에서도 휠로 확대한다 | 겹침 보기 휠 확대 지원 |
| 토글이 S3 뿐 아니라 DB 도 바꾼다 | 환경 토글 DB 반영 추가 |

## 절차

1. `git status` · `git diff HEAD` 로 실제 변경 확인 — 추측 금지.
2. 변경이 두 갈래 이상이면 **묻지 않고 나눠서 커밋**. 합쳐 달라는 명시 요청이 있을 때만 합침.
3. 관련 파일만 add. 무관한 파일 섞지 않음.
4. heredoc 으로 커밋 → `git log --oneline -1` 확인.

## 하지 않을 것

- 요청 없는 `git push`
- `--no-verify`, `--amend` (명시 요청 없는 한)
- main 직접 커밋 — 브랜치부터 만들지 묻는다
