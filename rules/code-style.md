# 코드 스타일

- 이름으로 설명한다. 주석으로 설명해야 하면 이름 · 구조를 고친다
- 주석은 꼭 필요할 때만 짧게 쓰고 "왜" 만 남긴다. 음슴체 · 개조식으로 쓴다
- 같은 로직을 반복하지 않는다. 새로 쓰기 전에 비슷한 함수 · 컴포넌트 · 모듈이 이미 있는지 찾아서 쓴다
- 처음부터 모듈화를 고려하고 만든다. 입력 · 출력이 분명한 작은 단위로 나누고, 호출부에 묶이지 않는 부분은 공용 모듈로 뺀다
- 실패는 조용히 넘기지 않는다 (fail-loud). 부분 성공을 성공으로 보고하지 않는다
- workaround 를 만들지 않는다. 원인을 고치고, 못 고치면 멈추고 보고한다
- 폴백은 명시적으로 요청받았을 때만 만든다. 기본값으로 대신하기 · 조용한 재시도 · 다른 경로로 우회하기가 모두 폴백이다
- 에러 메시지는 `짧은 설명 (디버그 값)`. 서술문(`~다` · `~습니다`) 금지. 괄호엔 되짚을 값(HTTP 상태 · 이름 · 인덱스), 같은 값을 `details` 에도
- 조치 문구(`~하세요`)는 서버가 아니라 클라이언트가 에러 코드별로 붙인다. 서버는 무엇이 틀렸는지만 말한다
- 원문 SQL 은 한 파일에 모으고, 쿼리마다 왜 ORM 이 아니라 원문인지 남긴다
- 페이지네이션은 api 에서 구현한다. 서버가 `limit` + 커서(또는 offset)로 잘라 주고 다음 커서 · 전체 개수를 같이 내려준다. 전체를 받아 프론트에서 자르지 않는다. 그렇게 자를 목록이면 필터 · 정렬 · 검색도 서버에서 한다
