## 16 implementation-plan · 구현 계획

`16-implementation-plan.html`

**뼈대**
1. eyebrow + 제목 + 요청 원문 박스(`prompt-box`)
2. 요약 스트립 — 4칸 그리드 (공수 · 건드리는 표면 · 새 테이블 · 위험도). 한 칸은 accent 색
3. `01`~`06` 번호 붙은 섹션. 번호는 mono 배지
4. 마일스톤 타임라인 — `grid-template-columns: 120px 28px 1fr` (시점 · 점/선 · 본문). 완료는 점 색 변경
5. 데이터 흐름 SVG (동기=실선, 비동기=점선)
6. 목업 2단 — 픽셀 완성도 말고 라벨 A/B 로 지시
7. 위험 표 — 위험 / 심각도 / 완화 열

**언제** 구현 계획, 스펙, 착수 문서.
**핵심** 각 마일스톤이 독립적으로 리뷰 가능해야 한다. 마일스톤마다 태그(`api` `db` `web`)로 범위를 보인다.

## 13 flowchart · 주석 달린 흐름도

`13-flowchart-diagram.html`

**뼈대** 왼쪽 인라인 SVG 흐름도 + 오른쪽 상세 패널. 노드 `<g class="node" data-k="...">`, 클릭 시 `DETAIL[k]` 로 패널 갱신(제목·메타·설명·코드). 첫 노드는 로드 시 `active`.

**언제** 배포 파이프라인, 요청 경로, 상태 전이, 실패 분기.
**핵심**
- 간선 의미를 색·점선으로 구분 (`.edge.yes` olive 실선 / `.edge.no` rust 점선) + `marker-end` 화살표를 색마다 하나씩
- 분기는 마름모 `path`, 종단은 라운드 `rect`
- 노드에 소요시간·명령을 메타로 (`~2 min`, `argo rollouts`)
- 범례 필수
- **실패 경로를 반드시 그린다.** 성공만 그린 흐름도는 반쪽

## 18 / 19 / 20 · 편집 인터페이스

`18-editor-triage-board.html` · `19-editor-feature-flags.html` · `20-editor-prompt-tuner.html`

**뼈대** 값을 실제로 고치는 화면 + 결과를 붙여넣을 수 있게 내보내기.
